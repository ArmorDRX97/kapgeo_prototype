# Карта взаимосвязей — внутренний модуль команды

Решение пользователя от 14.10.2026: перенести локальный React-атлас в основной проект, сохранить его собственное оформление, код и документацию; показывать вход в меню профиля как инструмент разработчиков, аналитиков и авторов контента. Это заменяет прежнюю границу «только отдельное приложение вне Git/CI» для перенесённого модуля.

Вход: **профиль → Карта взаимосвязей → Для команды · разработка**. Маршрут `/team/knowledge-map` открывает полноэкранный атлас с отдельной тёмной шапкой, фиолетовой границей, отметкой `TEAM / DEV` и кнопкой «В прототип». Рабочие модули и их меню не отображаются внутри инструмента. Возврат восстанавливает исходный маршрут вместе с query-параметрами. При прямом входе возврат ведёт в рабочую область выбранной персоны.

## Границы

- Весь runtime атласа находится в этом каталоге; единственный общий контракт с оболочкой — `integration/protocol.ts`. Он содержит режим/ID понятия и безопасный адрес возврата, без бизнес-данных.
- `internal/knowledge-map.html` — второй HTML entry Vite. Основная страница размещает его в iframe того же приложения. Отдельный сервер, репозиторий или deployment атласу не нужны.
- iframe отделяет DOM, CSS, Tailwind preflight, переменные темы, React Flow, диалоги и внутреннюю hash-навигацию. Это граница оформления и исполнения, **не механизм разграничения доступа или защиты секретов**. Статический образовательный материал не содержит закрытых данных.
- Хост страницы использует токены оболочки только для внутренней шапки и входа из профиля. CSS атласа не импортируется в приложение; CSS приложения не импортируется в атлас. Крупный граф и ELK Worker загружаются после входа в инструмент.
- Нет импортов repository, IndexedDB БГД, данных разрезов/интерпретации, продуктовых форм, permissions или бизнес-команд. Обратные импорты из атласа за пределы каталога запрещает проверка `check-isolation.mjs`.
- Учебный JSON — источниковый снимок системы по `docs-ref/knowledge`, а не зеркало текущего React-прототипа. Решение пользователя 16.10.2026: использовать только разобранные материалы из `docs-ref/files`; готовность, заглушки и ограничения фронтенда не определяют содержание карты. Старое поведение, требования ТС и открытые вопросы различаются через `knowledgeBasis` и `evidence`.
- Сессия входа проверяется основным router. В текущем демонстрационном приложении внутренний вход доступен всем вошедшим участникам независимо от бизнес-роли; отдельной роли разработчика здесь нет. Видимая отметка команды не заявляет production ACL. Публичные статические assets нельзя считать приватными.
- Runtime не требует старой локальной папки `kapgeo-knowledge-map/`; в текущем checkout её нет. Удалённые документы и архив не восстанавливаются и не используются как основания.

## Состав

Компактная компоновка от 16.10.2026: верхняя брендовая шапка и большой заголовок убраны; поиск и учебные маршруты находятся в строке высотой 56 px над инструментами карты. Навигация на узком экране открывается кнопкой рядом с поиском, справка остаётся в боковом меню. При viewport 1440×1000 высота карты увеличилась с 716,25 до 860 px; поиск Ctrl/⌘ K, reload, маршруты и мобильное меню проверены в браузере.

`app/` — bootstrap, стили, lazy-loading и error boundary; `pages/` — композиция атласа; `widgets/` — граф, навигация, подробности; `features/` — поиск, фильтры, путь, обучение, экспорт и состояние; `entities/knowledge/` — Zod-модель/индекс/алгоритмы; `shared/` — собственный Dialog и ELK Worker; `data/` — понятия, связи, области, маршруты и источники; `checks/` — модельные и интеграционные тесты; `docs/` — документация только этого инструмента.

Текущий срез: **230 понятий, 661 связь, 10 областей, 18 специалистов, 14 маршрутов**. Все **122 содержательных источника** (40 документов, 82 видео) доступны через пять групп источников; ещё 11 catalog IDs сохранены как явно подписанные aliases для совместимости, не независимые свидетельства. 18 сквозных процессов имеют собственные карточки с входами и выходами. Пять верхних функциональных контуров: геология (включая БГД), технология, моделирование, ЭАМ и общие административные правила.

## Сборка

Команды выполняются из корня основного проекта:

```text
npm run dev
npm run validate:knowledge-map
npm run typecheck
npm run test
npm run lint
npm run build
npm run preview
```

Общий build валидирует JSON, границы импортов и отдельные HTML/CSS entry. Dependencies перенесены в корневой package/lock: React Flow 12.12.0, ELK 0.12.0, html-to-image 1.11.13, Tailwind/@tailwindcss/vite 4.3.3. React/ReactDOM, Lucide и Zod используются из общего набора зависимостей; внутри iframe запускается собственный React root. `@import "tailwindcss" source(none)` отключает сканирование классов продукта: стили атласа заданы его собственным CSS.

В production используется общий base `/kapgeo_prototype/`. Основной router работает с `#/team/knowledge-map?mode=…&node=…`, iframe — со своим `#mode=…&node=…`. Узкий postMessage-контракт проверяет origin, source окна, channel и значения режима/ID. Внутренние переходы заменяют текущий URL, не создают цепочку дополнительных browser Back; кнопки истории атласа остаются самостоятельными. Скопированная ссылка ведёт на маршрут основного приложения, без адреса iframe и адреса чужого рабочего объекта.

Прогресс, координаты, закрепления и настройки хранятся только в `kapgeo.knowledge-map.v1`. Если прежнее приложение работало на том же origin, сохранённое состояние читается без миграции. С другого origin/порта localStorage автоматически перенести нельзя. При недоступном хранилище работает текущая сессия с предупреждением. Закрытие документа сохраняет последний контекст через `pagehide`.
