# Каротажи БГД: таблицы и параметры измерений — 15.10.2026

## Источники и границы

Уточнение пользователя: в карточке скважины нужны отдельные вкладки «Контрольные каротажи» и «Все каротажи», табличное представление, без колонки «Канал» и без графического отображения кривых. Для формы добавления пользователь отдельно назвал зонд, глубину, шаг и диаметр. Дополнительный источник — переданный HTML экспорт страницы Confluence `97616184` «Каротажи» и приложенный к сообщению макет.

Страница РП подтверждает список атрибутов каротажа и таблицу результатов «глубина — измеренное значение», операции добавления/удаления строки, сохранение/отмену, подтверждение удаления набора и ограничение на несколько основных наборов одного типа. Для явно запрошенного прототипного среза реализованы два списка, табличные атрибуты, зонд, начало/конец глубины, шаг, диаметр прибора и скважины, комментарий и таблица значений. Графический preview отключён. Оператор и прибор остаются существующими полями формы.

## Поведение

- «Контрольные каротажи» показывает записи с явным `survey.isControl`; «Все каротажи» показывает полный список. Признак доступен в форме создания/редактирования. При чтении старого демо-набора с отсутствующим признаком контрольный набор распознаётся по существующему имени «Контрольный…».
- Реестр — настоящая таблица с типом, датой, оператором, прибором, зондом, признаком основного набора, глубиной, шагом, диаметром прибора/скважины и статусом. Длинная таблица прокручивается внутри своего блока; числовые столбцы выровнены по правому краю.
- Выбор записи показывает таблицу замеров: глубина и столбцы выбранных кривых с единицами. Значения — локальный синтетический пример. Вкладка позволяет редактировать значения/глубину, добавлять и удалять строки, сохранять или отменять их; несохранённая таблица блокирует переключение набора/вкладки и защищает переход по БГД.
- Графический preview временно скрыт. Код и операции рендеринга кривых не показываются в этом рабочем месте.
- Добавление/редактирование хранит зонд, максимальную глубину `to`, шаг, диаметры прибора/скважины в сантиметрах и признак контрольной записи в существующем локальном `well-log-v2` workspace. Новые API и серверное хранилище не добавлены.

## Проверка

Компонентные тесты проверяют обе вкладки, отсутствие «Канал» в таблице атрибутов, скрытый график, сохранение измерений и новых полей, а также перенос новой контрольной записи во вкладку контрольных. Модель валидирует положительные диаметры и длину зонда. Применяются общие проверки БГД из корневого `AGENTS.md`; результаты актуальной полной проверки фиксируются в `docs/implementation-status.md`.

## Что не следует считать подтверждённым

В самой РП отмечены открытые вопросы заказчику: права на операции, правила глубины/значений, повторные глубины, поведение при удалении основного набора и связь с исходным набором. Они не превращены здесь в бизнес-правила. Контрольность вынесена в явный локальный флаг, поскольку отдельные вкладки требуют однозначной классификации; производственная классификация остаётся на согласование. Демонстрационные точки не являются фактическими измерениями.
