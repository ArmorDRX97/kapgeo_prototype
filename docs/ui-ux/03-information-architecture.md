# Информационная архитектура и навигация

## 1. Целевая модель

AI KAPGEO проектируется как единое web-приложение с общим shell и предметными рабочими областями. Пользователь сохраняет организационный и временной контекст при переходе между геологией, технологией, моделированием и аналитикой.

Главный принцип: навигация идёт от задачи и объекта, а не от структуры исходной базы данных.

## 2. App shell

### 2.1. Верхняя панель

- логотип и название среды: `DEMO`, `TEST`, `PROD`;
- глобальный выбор контекста;
- дата/период с индикатором «на дату»;
- глобальный поиск и палитра команд;
- фоновые задачи;
- уведомления;
- справка;
- профиль, язык, тема и выход.

### 2.2. Левая навигация

Состав формируется по эффективным правам пользователя:

1. Главная;
2. Мои задачи;
3. Геология;
4. Технология;
5. Моделирование;
6. Аналитика;
7. Данные и отчёты;
8. Администрирование — только при наличии прав;
9. Избранное и недавние.

Раздел раскрывает локальную навигацию модуля. Меню можно свернуть до пиктограмм. Текущий раздел, несохранённые изменения и количество задач видимы постоянно.

### 2.3. Контекстная строка

`Организация / Предприятие / Месторождение / Участок / Блок / Объект`

Каждый сегмент — селектор и ссылка. Выбор родителя ограничивает доступные дочерние объекты и данные всех модулей. Рядом показываются:

- дата актуальности;
- версия или сценарий;
- статус данных;
- индикаторы качества и синхронизации;
- действие «Скопировать ссылку на текущий вид».

### 2.4. Рабочая область

Общий паттерн сложных экранов:

- заголовок, статус и основные действия;
- панель фильтров;
- основной canvas: карта, таблица, график, схема или редактор;
- правая панель инспектора;
- нижняя сворачиваемая панель событий, ошибок или временных рядов;
- вкладки связанных представлений.

## 3. Иерархия объектов

```text
Организация
└── Предприятие
    └── Месторождение
        ├── Рудное тело
        └── Участок
            ├── Горизонт / профиль
            ├── Эксплуатационный блок
            │   ├── Технологическая ячейка
            │   └── Скважина / наблюдательный объект
            └── Модель / расчётный проект
```

Иерархия не должна скрывать сетевые связи: скважина может входить в технологическую ячейку, профиль, контур запасов и расчётный сценарий одновременно. Эти связи показываются в карточке объекта отдельным графом.

## 4. Центральные точки входа

### 4.1. Главная роли

Не универсальный dashboard, а адаптированный рабочий стол:

- «Продолжить работу»;
- мои задачи и просрочки;
- объекты с проблемами качества;
- важные события смены/суток;
- статусы расчётов и импортов;
- избранные карты и отчёты;
- согласования;
- быстрые действия роли.

### 4.2. Единая карточка скважины

Основной межмодульный узел. Шапка содержит код, тип, координаты, принадлежность, статус, дату и качество. Вкладки:

1. обзор;
2. паспорт и конструкция;
3. геология и керн;
4. ГИС и интерпретация;
5. пробы и лаборатория;
6. технологический режим;
7. оборудование;
8. РВР;
9. модель и прогноз;
10. документы;
11. версии и аудит.

Вкладки доступны по правам. Ссылка на объект сохраняет контекст, дату, активную вкладку и выбранный интервал.

### 4.3. Карточка блока

Объединяет паспорт запасов, технологическую схему, баланс, оборудование, модель, показатели и отчётность. Это основная точка для R3, R6, R11 и R12.

## 5. Карта маршрутов

Маршруты логические; фактический prefix приложения может быть изменён без изменения IA.

| Область | Базовый маршрут | Назначение |
|---|---|---|
| Авторизация | `/auth/*` | Вход, MFA, запрос доступа, ошибки сессии |
| Главная | `/home` | Ролевой рабочий стол |
| Задачи | `/work` | Личная очередь и согласования |
| Объекты | `/objects/:type/:id` | Унифицированные карточки |
| Геология | `/geology/*` | БГД, ГИС, интерпретация, разрезы, запасы |
| Технология | `/technology/*` | Схема, замеры, растворы, оборудование, РВР |
| Моделирование | `/modeling/*` | Проекты, сетки, параметры, запуски, результаты |
| Аналитика | `/analytics/*` | Карта, показатели, отклонения, рекомендации |
| Данные | `/data/*` | Импорт, экспорт, отчёты, качество, фоновые задачи |
| Администрирование | `/admin/*` | Доступ, справочники, интеграции, аудит, AI |
| Профиль | `/profile/*` | Личные настройки и безопасность |

Обязательные query-параметры: `asOf`, `context`, `scenario`, `view`, `selection`. Состояние фильтра, которое важно для совместной работы, должно кодироваться в URL; временное состояние панелей может храниться локально.

## 6. Поиск и команды

### Глобальный поиск

Ищет по коду, названию, внешнему ID, координатам и содержимому разрешённых документов. Результаты группируются по типу и показывают контекст, статус и совпавшие поля. Недоступные объекты не раскрываются даже названием.

### Палитра команд

Открывается с клавиатуры и позволяет:

- перейти к экрану или объекту;
- создать разрешённый объект;
- запустить импорт/отчёт;
- сменить контекст и дату;
- открыть справку по текущему экрану.

## 7. Навигационные паттерны

| Ситуация | Паттерн |
|---|---|
| обзор множества объектов | list/map + фильтры + сохранённый вид |
| работа с одним объектом | карточка с вкладками и инспектором |
| сравнение | split view или таблица различий |
| многошаговое действие | wizard с сохранением черновика |
| сложный редактор | canvas + дерево + inspector + история |
| оперативное событие | drawer без потери текущего контекста |
| необратимое действие | подтверждение с причиной и последствиями |
| долгая операция | фоновая задача с прогрессом, журналом и уведомлением |

## 8. Сквозные связи модулей

| Источник | Целевой переход | Передаваемый контекст |
|---|---|---|
| ГЕО: скважина/интервал | ТЕХ: техпаспорт | ID скважины, версия геоданных, дата |
| ГЕО: утверждённые запасы | МОД: входной набор | блок, версия контуров и параметров |
| ТЕХ: режим/замеры | МОД: граничные условия | объект, период, набор измерений |
| МОД: опубликованный расчёт | ЭАМ: факт/модель/прогноз | scenario/run/version |
| ЭАМ: отклонение | ГЕО/ТЕХ: исходный объект | дата, выборка, метрика, фильтр |
| Любой модуль | отчёт/экспорт | снимок контекста и разрешённая выборка |

Каждый переход показывает, какая версия данных открыта. Если источник устарел относительно опубликованной версии, пользователь видит предупреждение и может открыть diff.

## 9. Временной контекст

Система различает:

- текущие данные;
- состояние «на дату»;
- период измерений;
- версию справочника;
- версию бизнес-объекта;
- время расчётного сценария.

Переключение даты не должно молча подменять данные. В режиме прошлого времени редактирование запрещено; доступна команда «Создать новую версию на основе этой».

## 10. Состояния URL и возврат

- deep link открывает тот же объект, вкладку, дату и разрешённый фильтр;
- после входа пользователь возвращается на исходный URL;
- после ошибки прав показывается безопасная страница с доступными альтернативами;
- «Назад» возвращает к прежней выборке и позиции прокрутки;
- несохранённая форма блокирует случайный уход;
- закрытие drawer не перезагружает основной экран.

## 11. Responsive-стратегия

- **1440 px и шире:** полный профессиональный workspace;
- **1280–1439 px:** сжатые боковые панели;
- **1024–1279 px:** одна панель за раз, упрощённая таблица;
- **768–1023 px:** просмотр, ввод простых форм, задания РВР, согласование;
- **до 767 px:** уведомления, задачи, профиль, карточка в режиме чтения; сложные редакторы дают ссылку «Открыть на рабочем экране».

## 12. Обязательные состояния каждой страницы

Для реестра экранов проверяются:

1. загрузка;
2. данные;
3. пусто;
4. нет результатов фильтра;
5. частичные данные;
6. ошибка с повтором;
7. нет доступа;
8. offline/устаревший cache, если применимо;
9. режим чтения;
10. несохранённые изменения;
11. конфликт версии;
12. фоновая операция.

## 13. Правила именования

- пользователю показывается предметный термин, а не имя таблицы или API;
- одно действие имеет одно название во всех модулях;
- `Удалить` используется только при реальном уничтожении, в остальных случаях — `Архивировать`, `Отозвать`, `Исключить`;
- статус и дата всегда сопровождают опубликованные расчёты и утверждённые данные;
- сокращение раскрывается tooltip при первом использовании на экране.
