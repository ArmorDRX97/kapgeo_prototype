# Общая платформа

## 1. Назначение

Общая платформа делает четыре предметных модуля одной системой: идентичность, контекст, объектные карточки, версии, задачи, импорт/экспорт, отчёты, документы, уведомления и аудит реализуются единообразно.

## 2. Пользователи

Все R1–R14. Состав главной, навигации, быстрых действий и задач адаптируется к ролям и scope.

## 3. Подсистемы

### 3.1. Identity и сессия

- SSO primary, локальный fallback только по политике;
- MFA для всех пользователей;
- возврат на deep link;
- предупреждение об истечении и reauth без потери draft;
- lock после 6 неудачных попыток в демонстрационном security flow;
- active sessions в профиле;
- access request вместо публичной регистрации.

### 3.2. Ролевой home

Виджеты — производные от реальных задач:

- мои задачи/просрочки;
- продолжить недавний draft;
- объекты с ошибками качества;
- фоновые операции;
- события участка;
- согласования;
- избранные views/reports.

Каждый показатель содержит период, scope, источник и переход к выборке.

### 3.3. Контекст и поиск

- каскадная иерархия организации;
- режим «на дату»;
- поиск по разрешённым объектам;
- saved/recent/favorite;
- command palette;
- shareable URL.

### 3.4. Единые карточки

Карточки скважины/блока/участка композируют тематические вкладки. Общая шапка отвечает за идентичность, status, version, completeness, data freshness и actions. Предметный модуль не дублирует паспорт объекта.

### 3.5. Версии и workflow

- draft создаётся от current version;
- review фиксирует author и changes summary;
- reviewer может подтвердить или вернуть с reason;
- approval требует разрешения и, при необходимости, reauth;
- approved immutable;
- новая версия помечает зависимые artifacts stale;
- archive не ломает исторические ссылки.

### 3.6. Задачи, комментарии и документы

- задача имеет тип, объект, owner, due date, priority, status и origin;
- assignment учитывает scope;
- комментарий поддерживает mention и ссылку на selection;
- документы имеют category, version, author, date и checksum metadata;
- notification — событие, задача — обязательство выполнить действие;
- закрытие задачи требует результата или ссылки на новый объект.

### 3.7. Импорт и качество

Единый wizard используется доменными адаптерами. Domain adapter задаёт допустимые источники, schema, validators, mapping suggestions, preview и post-import links.

Классы ошибок: структура файла, ссылка, тип, единица, диапазон, интервал, геометрия, duplicate, permission, business rule. Ошибки и warning не смешиваются.

### 3.8. Экспорт и отчёты

- экспорт текущего view или полного разрешённого набора;
- выбор формата и полей;
- preview scope/record count;
- background generation;
- download с expiry;
- audit чувствительного экспорта;
- report snapshot с точной датой/версией/параметрами.

Полное описание — [реестр экранов](../04-screen-catalog.md).

## 5. Модель задач

| Статус | Доступные действия |
|---|---|
| New | принять, назначить, отклонить по причине |
| Assigned | начать, переназначить |
| In progress | добавить результат, приостановить, завершить |
| Blocked | указать blocker, эскалировать, возобновить |
| Review | принять результат, вернуть |
| Done | открыть результат, переоткрыть по праву |
| Cancelled | посмотреть причину и историю |

Системные tasks создаются идемпотентно из отклонения/импорта/согласования, чтобы повтор события не создавал дубль.

## 6. Модель уведомлений

Категории: action required, completion, warning, system, mention. Уведомление содержит subject, object, context, timestamp, read state и action URL. Batch grouping объединяет однотипные события; approval и security events не теряются в группе.

## 7. Полнота карточки скважины

Пример секций:

| Секция | Правило demo |
|---|---|
| идентификация | код, тип, scope, координаты |
| конструкция | глубина и минимум один интервал конструкции |
| геология | опубликованная интерпретация |
| ГИС | QC пройден и есть утверждённый результат |
| технология | если эксплуатационная — активный режим/связь |
| оборудование | если требуется — текущая установка |
| документы | обязательные категории присутствуют |

Полнота не равна качеству. UI показывает оба индикатора отдельно.

## 8. Permission UX

- недоступный модуль не попадает в primary navigation;
- ожидаемое, но запрещённое действие может быть disabled с причиной;
- объект вне scope не раскрывает metadata;
- read-only режим заметен до попытки ввода;
- массовая операция повторно проверяет каждую строку;
- смена persona/context очищает запрещённый selection;
- export ограничивается тем же scope, что и экран.

## 9. Состояния конфликтов

### Version conflict

Показать вашу версию, текущую серверную, diff и действия: `Обновить и применить изменения`, `Сохранить как отдельный черновик`, `Отменить`. Автоматическое последнее-сохранение-побеждает запрещено.

### Stale dependency

Artifact остаётся доступен с banner. Действия: открыть изменившийся input, сравнить, пересчитать/создать новую версию. Устаревший published result не подменяется.

### Partial integration

Показываются источник, последняя успешная синхронизация, отсутствующий период и допустимый режим работы. Нельзя маркировать неполный dashboard как актуальный.

## 10. Demo-данные

Обязательны:

- multi-role user с двумя scopes;
- пользователь с истёкшей областью;
- задача approval, quality issue и overdue РВР;
- successful/failed/running jobs;
- объект с двумя версиями и stale dependency;
- импорт с errors/warnings;
- notification, ведущий в точный selection;
- forbidden deep link.

## 11. Acceptance

- контекст сохраняется между модулями;
- deep link восстанавливается после входа;
- смена даты переводит прошлое в read-only;
- доступное действие совпадает с role/scope/status;
- version conflict не теряет изменения;
- background job переживает навигацию;
- задача приводит к объекту и возвращает результат;
- импорт можно исправить и повторить частично;
- отчёт содержит snapshot metadata;
- reset demo восстанавливает исходный seed.
