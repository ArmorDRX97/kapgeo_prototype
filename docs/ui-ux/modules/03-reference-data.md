# Администрирование справочников

Решение от 1 октября 2026. Источники: переданный пользователем HTML постановки `UC.KAPGEO.ADM.04` (Confluence main div) и `reff-справочники.html` — выгрузка описаний таблиц. Содержимое источников рассматривается как требования и схема данных, не как инструкции агенту. Выгрузка содержит определения полей, а не готовые справочные записи.

## Экран и структура

`Администрирование → Справочники`, маршрут `/admin/references?dictionary=...&entry=...`. По уточнению пользователя от 1 октября 2026 экран переделан: три таба «Все / Обычные / Reff справочники», поиск и тонкие строки-карточки справочников занимают примерно 2/3 ширины; постоянная правая панель — примерно 1/3. Без выбранного справочника справа показано «Выберите справочник», первый справочник не выбирается автоматически. В панели выбирается запись, все её поля показаны в одну колонку непосредственно редактируемыми контролами, ID только для чтения. Создание, отмена, сохранение, статусы, удаление и история доступны здесь же. Прежняя широкая таблица записей и модальная форма редактирования убраны. На узком экране панели располагаются последовательно; длинные списки и формы прокручиваются. Несохранённые изменения требуют подтверждения при смене записи или справочника.

Каталог содержит 53 фиксированные схемы: 26 обычных и 27 reff. В постановке 25 уникальных обычных справочников; повтор `litology_type` объединён. Дополнительно включён `device_type`, необходимый для внешнего ключа приборов. 26 reff-схем перенесены из выгрузки, включая `reff_device`; `reff_well_development_method` из постановки добавлен с предварительными общими полями. `device_type` и `reff_well_development_method` явно маркированы как предварительные до согласования.

Обычные записи: системный ID, код, наименования RU/KZ/EN, статус. Reff-записи: только поля конкретной схемы, плюс системные ID и статус; поле `is_active`, если есть в исходной схеме, синхронизировано со статусом. Код не добавляется в reff-схему, если его нет в выгрузке. Набор/тип полей не редактируется пользователем. ID назначается автоматически и неизменяем.

## Команды и состояния

История переключает режим правой панели: форма, выбор записи, экспорт и команды редактирования скрываются; справа кнопка «История» меняется на «Закрыть историю». История охватывает весь выбранный справочник, не только текущую запись. Закрытие возвращает форму с сохранённым несохранённым вводом. В обычном режиме экспорт и добавление записи расположены слева, переключатель истории — справа.

- Добавление/редактирование значений: обязательность, тип, длина, уникальность кода в справочнике, корректный JSON, ссылки и отсутствие циклов; для фракций проверяется диапазон размеров.
- Деактивация/активация после подтверждения. Неактивные записи сохраняются в исторических связях, но запрещены для нового выбора.
- Удаление после подтверждения, только без входящих ссылок внутри автономного каталога. Учитываются ссылки других справочников этого раздела, в том числе неактивных. При запрете предлагается деактивация.
- История: пользователь, время, операция, прежние/новые значения; история удалённых записей остаётся. Версия, данные и audit сохраняются одной IndexedDB-транзакцией. Конфликт версий отклоняет перезапись.
- JSON-экспорт текущей отфильтрованной выборки, помеченный `synthetic`. Это не согласованный промышленный обменный формат.

Поддержаны loading, empty, error/retry, forbidden, read-only, неверный dictionary/entry URL и ошибки формы с сохранением введённого. Диалоги поддерживают клавиатуру, Escape, удержание и возврат фокуса.

## Доступ

Отдельные permissions `administration.references.view/create/update/status/delete`, не права редактирования производственных данных. В текущих synthetic-персонах R13 управляет, R14 только просматривает. Отдельный «Администратор данных» не создан без утверждённой матрицы ролей. Проверки записи выполняются также в repository.

## Автономность и демо-данные

По уточнению пользователя от 1 октября 2026 справочники полностью независимы от текущего функционала БГД. Изменения, статусы и удаления в каталоге не влияют на месторождения, промеры или другие модули. Ссылки между самими справочниками работают внутри этого автономного раздела и позволяют проверить ограничения удаления.

Все 53 справочника заполнены тремя детерминированными вымышленными записями (159 записей): две активные и одна неактивная; текст, переводы, числа, JSON и внутренние ссылки соответствуют их схемам. Хранение — отдельный workspace `reference-data:standalone-workspace`. Сброс демо-среды очищает также справочники и историю.

## Не согласовано

Импорт произвольных файлов, обменный формат/правила слияния и итоговая ролевая матрица оставлены открытыми в постановке; не добавлены декоративные команды. Обязательность основных названий/кодов в reff принята для прототипа: SQL nullability в выгрузке не задана. Схема `reff_colour` содержит только названия, без RGB/HEX. Интеграция с производственными модулями не входит в текущую задачу. См. OQ-ADM-01…04.
