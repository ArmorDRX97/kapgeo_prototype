# Дизайн-система AI KAPGEO

## 1. Визуальная концепция

Рабочее название направления: **Industrial Intelligence** — современный инженерный интерфейс, в котором сложные данные выглядят точными, спокойными и управляемыми.

Характер:

- профессиональный, а не рекламный;
- плотный, но не перегруженный;
- строгая иерархия вместо декоративных карточек;
- карта, разрез, график и таблица — равноправные рабочие инструменты;
- цвет сообщает состояние или тип данных, а не украшает экран;
- AI визуально объясним и отделён от утверждённого человеком результата.

Ниже задана нейтральная временная тема. **OPEN:** после получения брендбука сопоставить корпоративные цвета, шрифты, логотип и правила co-branding без изменения семантических токенов.

## 2. Темы

### Light — основная

Используется для реестров, форм, согласования, отчётов и администрирования.

### Scientific dark — рабочая

Используется для карт, каротажных кривых, разрезов и моделирования. Shell может оставаться светлым; тёмным становится canvas. Пользователь может переключить весь интерфейс в тёмную тему из профиля.

### High contrast

Дополнительный режим для слабовидящих и сложных условий на производственном экране. Он не должен зависеть от browser forced-colors для базовой читаемости.

Геологические литологии и стратиграфия используют утверждённые предметные легенды, а не общую UI-палитру.

## 4. Типографика

- основной стек: `Inter, "Segoe UI", Arial, sans-serif`;
- моноширинный: `JetBrains Mono, Consolas, monospace` для кодов, координат и логов;
- базовый размер: 14 px; текст форм 14–16 px;
- малый служебный текст: 12 px; размеры меньше 12 px в интерфейсе не используются;
- line-height: 1.4–1.5;
- заголовки: 28/34, 22/28, 18/24, 16/22;
- табличные числа используют `font-variant-numeric: tabular-nums`;
- единица измерения визуально вторична, но остаётся рядом со значением.

## 5. Сетка, плотность и размеры

- базовая единица spacing: 4 px;
- ряд: 4, 8, 12, 16, 20, 24, 32, 40, 48;
- рабочая сетка: 12 колонок, gutter 24 px на desktop;
- левая навигация: 248/64 px;
- inspector: 360–440 px;
- минимальная интерактивная зона: 40×40 px, для полевого tablet — 44×44 px;
- радиус: 6 px controls, 8 px panels, 12 px modals;
- тени используются только для слоёв, а не для каждой карточки.

Три режима плотности: `comfortable`, `compact`, `field`. Таблицы по умолчанию compact; формы comfortable; РВР на планшете field.

## 6. Иконки и иллюстрации

- единый outline-набор 20/24 px;
- предметные иконки проходят проверку специалистов;
- destructive actions не обозначаются одной непонятной пиктограммой;
- loading не имитирует прогресс, если процент неизвестен;
- пустые состояния используют небольшие схемы или иконки, без декоративных stock-иллюстраций.

## 7. Базовые компоненты

### Actions

- Button: primary, secondary, quiet, danger, icon;
- SplitButton для `Сохранить` / `Сохранить и отправить`;
- MenuButton для экспортов и вторичных операций;
- ButtonGroup для режимов карты/графика;
- Command item с shortcut.

На странице не более одного визуально доминирующего primary action в одной зоне.

### Inputs

- text, textarea, number + unit, masked code;
- date, date-time, date range, «на дату»;
- combobox с серверным поиском;
- tree select для иерархии;
- coordinate input с системой координат;
- interval input `от–до` с визуализацией перекрытий;
- file dropzone;
- expression/parameter editor;
- segmented control, switch, checkbox, radio.

Ошибки показываются у поля и в summary формы. Значения не очищаются после server error.

### Data display

- DataGrid с virtual scroll, sticky headers, pin columns, grouping и column presets;
- ObjectCard и ObjectHeader;
- StatusBadge, QualityBadge, VersionBadge, SourceBadge, AIBadge;
- Timeline и AuditEvent;
- KPI tile только для показателей с единицей, периодом и источником;
- DefinitionList для паспорта;
- EmptyState, ErrorState, Skeleton;
- DiffViewer для полей, интервалов, геометрии и таблиц.

### Navigation

- AppNav, Breadcrumb/ContextBar, Tabs, Stepper;
- SavedView selector;
- BackLink с восстановлением selection;
- Drawer, Inspector, BottomPanel;
- pagination только там, где выбор страниц значим; для рабочих таблиц — virtual scroll.

### Feedback

- inline validation;
- toast для обратимого локального успеха;
- persistent banner для деградации/устаревших данных;
- notification для завершения фоновой работы;
- confirm dialog для действий с последствиями;
- progress + current stage + log link для долгой операции.

## 9. Карты, разрезы и графики

- legend интерактивна и объясняет `No data`, `Not applicable`, `Invalid`;
- hover даёт краткую подсказку, click фиксирует selection;
- zoom не меняет агрегирование без явного индикатора;
- карта имеет масштаб, координаты, север, дату и систему координат;
- график имеет единицы, временную зону, gap-индикацию и источник;
- синхронный crosshair связывает карту, таблицу и график;
- пользователь может сохранить viewport, слои и фильтр как вид;
- PNG/SVG-экспорт содержит legend, дату и metadata snapshot.

## 10. Таблицы

- первая колонка идентифицирует объект и остаётся закреплённой;
- сортировка видима и поддерживает несколько полей;
- фильтры различают «пусто», ноль и `нет данных`;
- массовое выделение показывает точное количество, включая фильтрованные страницы;
- inline-edit применяется только к простым контролируемым полям;
- важные сложные изменения открывают форму/inspector;
- clipboard paste проходит валидацию до сохранения;
- экспорт наследует текущий фильтр, но показывает полный состав полей перед запуском.

## 11. Формы и редакторы

- форма разбивается по бизнес-смыслу, не по таблицам БД;
- обязательность и единица видны до ввода;
- черновик автосохраняется только с явным индикатором;
- вычисляемое поле показывает формулу/источник;
- изменение, влияющее на расчёты, помечает зависимости устаревшими;
- недоступное право объясняется, а не просто скрывается, если действие ожидаемо пользователю;
- destructive и approval actions требуют причины;
- wizard можно покинуть и продолжить позднее.

## 12. Статусы и AI

Предметный статус (`На проверке`) отделён от технического (`Синхронизация задержана`). AI-результат всегда содержит:

- label `AI`;
- модель и версию;
- время запуска;
- confidence/качество с расшифровкой;
- исходные данные;
- объяснение и ограничения;
- решение человека и автора решения.

Текст `AI рекомендует` нельзя заменять на `Система решила`.

## 13. Motion

- 120–180 ms для controls, 180–240 ms для drawer;
- никаких анимаций в больших таблицах и при массовом обновлении данных;
- `prefers-reduced-motion` отключает непринципиальные переходы;
- изменение карты или фильтра не должно вызывать скачок layout.

## 14. Доступность

Цель — WCAG 2.2 AA для shell, форм, таблиц и основных workflows.

- полная клавиатурная навигация и видимый focus;
- логический порядок заголовков и landmarks;
- label и description для полей;
- сообщения ошибок связаны с полем;
- контраст текста и controls проверяется автоматически и вручную;
- canvas имеет доступное табличное/текстовое представление ключевых данных;
- графики сопровождаются summary и таблицей;
- tooltips не являются единственным источником информации;
- screen reader объявляет завершение фоновой операции без перехвата focus.

## 15. Локализация

- RU/KZ/EN переключаются без выхода;
- UI не собирает предложения конкатенацией;
- число, дата, десятичный разделитель и единицы форматируются locale-aware;
- русский текст принимается как наиболее длинный baseline, но казахские строки проверяются отдельно;
- коды объектов, формулы и утверждённые обозначения не переводятся;
- терминология хранится в глоссарии с владельцем перевода.

## 16. Обязательные Storybook-состояния

Для каждого переиспользуемого компонента: default, hover, focus, active, disabled, loading, empty, error, read-only, long text, RU/KZ/EN, light/dark/high-contrast. Для предметных компонентов добавляются realistic density и данные с аномалиями.

## 17. Антипаттерны

- dashboard из одинаковых карточек без следующего действия;
- скрытая горизонтальная прокрутка;
- модальный диалог поверх модального диалога;
- цветовая «радуга» для статусов;
- один гигантский экран со всеми полями сущности;
- 3D только ради эффектной демонстрации;
- hamburger menu на desktop;
- fake precision без единиц и источника;
- автоматическое принятие AI;
- toast как единственное подтверждение важной операции.
