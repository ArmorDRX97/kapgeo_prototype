## Зафиксированные решения

- `main` содержит рабочую БГД и расширяемый shell; полный прежний прототип хранится в `archive/full-prototype-2026-09-15`;
- переключатель `Минимум` удалён;
- восстановлены 14 synthetic-персон, доступ к модулям рассчитывается по permission;
- создание месторождения перенесено в `/admin` и доступно R13;
- экскурсия удалена из `main`, но сохранена в архивной ветке для будущей адаптации под БГД;
- production backend и реальные данные не входят в текущий DoD.

## Открытые вопросы

- OQ-BGD-02: backend contract и миграция IndexedDB prototype data;
- OQ-BGD-03: утверждённые формулы рудных интервалов и метропроцента;

- OQ-BGD-05: окончательный состав RU/KZ/EN-справочников.
- OQ-ADM-01: итоговые разрешения «Администратора данных» из UC.KAPGEO.ADM.04; пока R13 управляет справочниками, R14 только читает, новая роль не вводится.
- OQ-ADM-02: форматы импорта/экспорта, обновление существующих кодов, частичные ошибки и правила слияния; текущий JSON-экспорт только synthetic, промышленный импорт не реализован.

### Решения первого среза, 05.10.2026

Этот раздел сохраняет историю первого среза; актуальные решения расширения ниже и в [текущем evidence](../task/interpretation-second-slice.md) заменяют прежние ограничения мощности/материалов/методов.

- По прямому уточнению пользователя делаем прототип в `C:/Projects/kapgeo`, на вымышленных данных, независимых от БГД. Это отменяет предложение первой заметки о переиспользовании БГД-контекста и данных на текущем этапе. Межмодульная интеграция отложена.
- Используем `@kapgeo/geo-viz/wellog` из `C:/Projects/frontent` как локальный snapshot пакета с адаптацией, а не новую стороннюю графическую библиотеку. Исходный frontend не меняется.
- Вход `/geology`; well/mode/from/to/selection в URL. Три режима одного рабочего места; собственный компактный список demo-скважин, общий UI-kit. На узком экране панели переходят друг под друга.
- `geology.interpretation.edit` для R1/R2/R13, дополнительно demo-scope/draft. Временная матрица не закрывает OQ-INT-04.
- Один явно demo-метод потенциал-зонда: значение ≥ порогу — проницаемый, линейное пересечение по полным исходным точкам, границы округляются до 0,1 м, NaN-участки остаются неизвестными. Тонкий интервал присоединяется к предыдущему известному, первый тонкий остаётся. Это допущения, не утверждённые формулы.
- Базовое соответствие керна: неизменная мощность, сдвиг внутри рейса, переворот; все связанные части проб/литология/промер меняются атомарно. Привязка пересоздаёт сводную литологию своего рейса; undo возвращает предыдущие ручные правки. Полный mapping остаётся будущим этапом.
- Сохранение автономно в localStorage, отдельная ревизия и сброс для каждой demo-скважины; без промышленного audit/утверждения. Предметная история до 40 команд.

- OQ-INT-01: фронтовые операции КП/ГС/ЛГХ/ТП реализованы во втором срезе; остаются предметные лабораторные схемы, новая проба через несколько сегментов и объединение разных номеров.
- OQ-INT-02: уточнить методы потенциал-/градиент-зонда и среднего КС: равенство порогу, интерполяция, плато/шум/null, крайние тонкие прослои, порядок округления. До согласования — явно synthetic demo-расчёт с записанными допущениями.
- OQ-INT-03: применимость ограничения legacy на мощность кернового сегмента с промером (исходная, 0,1 м или 0), правила преобразования связанных данных при сжатии/растяжении.
- OQ-INT-04: права геолога/геофизика на интерпретацию по видам данных, object scope, состояния результата и необходимость утверждения. `geology.view` само по себе не разрешает редактирование.
- OQ-INT-05: единый источник проб и производных сводных данных при наличии отдельных `WellCoreWorkspace` и `WellGeologyWorkspace`; реакция mapping на изменение исходных данных; совместное редактирование сводной литологии через БГД и интерпретатор.
- OQ-INT-06: крайние случаи удаления/overwrite, полный набор свойств для auto-merge и разрешённый диапазон сводной колонки после каскадного сдвига.

### Решения расширения, 05.10.2026

- Минерализации — канонический набор без учёта порядка; auto-merge литологии сравнивает породу/набор/цвет/примечание. Цвет керна отсутствует в литологии по каротажу. Группа удаляет только полностью попавшие строки. Технологическое удаление заполняется верхним соседом; без него остаётся gap.
- Потенциал/градиент и средний КС реализованы как demo по записанным правилам экстремумов/порогов/округления/gap. OQ-INT-02 остаётся промышленным согласованием, наличие кнопок и вычислений его не закрывает.
- Ограничение промера из РП применено: исходная мощность среза, 0,1 или 0; без промера — изменение. Привязка линейная/отражённая, связанная модель атомарная, исходные срезы не теряются. Общая контактная точка измерения принадлежит нижнему срезу. OQ-INT-03 остаётся вопросом применимости в новой промышленной системе.
- Каскадные изменения допустимы в 0…глубина скважины; пересечение сводных сегментов запрещено. Merge пока только внутри одного исходного core-id. Оригиналы с нулевой мощностью восстанавливаются, вставленные бескерновые удаляются полностью.
- Core-команды пересоздают сводную литологию всей области керна, включая её ручные правки, с предупреждением и undo. Явный reset по буровой колонке сбрасывает сводные правки/пробы и очищает undo; версия источника делает старое соответствие read-only до reset. Реальный источник БГД остаётся OQ-INT-05.
- Существующий localStorage namespace сохранён; старые mappings дополняются явными gap-сегментами, не заменяются fixture. Настройки колонок остаются временными. Утверждение/печать, реальная ACL, лаборатория и методы — следующие отдельные этапы.
