# Глоссарий и правила UX-текстов

## 1. Назначение

Глоссарий фиксирует единые русские термины для прототипа. Переводы на казахский и английский должны быть подтверждены предметными специалистами; нельзя переводить специализированные понятия автоматически без владельца термина.

## 2. Предметные термины

| Термин | Значение в UI | Правило употребления |
|---|---|---|
| AI KAPGEO | проектируемая корпоративная система | писать одинаково во всех языках до решения бренда |
| ПСВ | метод подземного скважинного выщелачивания | при первом упоминании раскрывать полностью |
| БГД | база геологических данных | в навигации предпочтительно `Геологические данные` |
| месторождение | верхний предметный контекст залежей и участков | не заменять словом `проект` |
| участок | производственная/геологическая область внутри месторождения | всегда показывать родительское месторождение |
| блок | контекстно: подсчётный или эксплуатационный блок | обязательно уточнять тип в заголовке |
| технологическая ячейка | связанная группа технологических объектов/скважин | не сокращать до `ячейка`, если контекст неоднозначен |
| скважина | единый объект с геологическими и технологическими представлениями | код показывать вместе с типом/назначением |
| керн | извлечённый материал бурения | интервалы указывать по глубине и единице |
| рейс бурения | интервал/операция проходки | не смешивать с рабочей сменой |
| выход керна | доля/процент извлечённого керна | всегда указывать форму значения и методику |
| литология | описание состава/типа пород | использовать утверждённый справочник и легенду |
| стратиграфия | отнесение интервалов к стратиграфическим подразделениям | отделять от литологии отдельным треком |
| проба | зарегистрированный образец с цепочкой лабораторной обработки | не называть результатом анализа |
| лабораторный результат | измерение по пробе, методу и единице | показывать QA/QC и источник |
| ГИС | геофизические исследования скважин | при первом упоминании раскрывать; не путать с GIS-картой |
| каротажная кривая | ряд измерений по глубине | показывать мнемонику, единицу и масштаб |
| LAS/DAT | форматы исходных геофизических данных | не переводить |
| интерпретация | экспертный/AI-результат обработки исходных данных | всегда указывать тип, версию и статус |
| геологическая колонка | шаблонное представление данных скважины по глубине | не использовать `колонка` для столбца таблицы рядом без уточнения |
| геологический разрез | профильное вертикальное представление | показывать трассу и версии источников |
| рудное тело | геологический объект/геометрия минерализации | не заменять подсчётным блоком |
| запасы | утверждаемый результат подсчёта по методу/категории | всегда указывать версию и дату |
| технологическая схема | узлы и действующие связи потоков | не называть простой картой |
| режим | интервально заданные параметры работы объекта | уточнять `проектный`, `плановый` или `фактический` |
| замер | значение, зарегистрированное во времени и источнике | не смешивать с расчётным показателем |
| раствор | продуктивный/закачной и иной тип по справочнику | тип обязателен в кратком представлении |
| материальный баланс | рассчитанное соотношение составляющих потока | раскрывать формулу и источники слагаемых |
| баланс кислоты | расчёт прихода/расхода/остатка и удельных показателей | всегда показывать единицы и норматив |
| оборудование | серийный объект с паспортом и событиями жизненного цикла | состояние отделять от места установки |
| ПНА | предметный тип оборудования из исходных материалов | раскрытие и классификацию подтвердить у R9 |
| РВР | ремонтно-восстановительные работы | при первом упоминании раскрывать полностью |
| наряд РВР | назначенное задание с этапами и ответственным | отделять от плана и результата |
| проект моделирования | контейнер входов, конфигурации, сценариев и запусков | не называть расчётом |
| сценарий | версия допущений/параметров относительно базы | visualization settings не являются сценарием |
| запуск расчёта | неизменяемый экземпляр выполнения сценария | в UI допустимо краткое `Запуск` |
| входной снимок | фиксированный набор версий входов | технический синоним `snapshot` не показывать без необходимости |
| факт | опубликованное наблюдаемое/учтённое значение | отделять от плана и расчёта |
| модель | рассчитанное значение конкретного запуска | указывать run/version |
| прогноз | значение на будущий период | показывать горизонт и источник |
| отклонение | зарегистрированное расхождение с эталоном/порогом | не равно ошибке данных |
| рекомендация | предлагаемое действие с доказательствами | не равно принятому решению |
| решение | зафиксированный выбор уполномоченного пользователя | должно создавать или закрывать обязательство |

## 3. Системные термины

| Термин | Значение/правило |
|---|---|
| Версия | зафиксированное состояние предметного объекта; использовать `Версия 3`, не `последняя копия` |
| Черновик | изменяемая неопубликованная версия |
| На проверке | профильная проверка правильности/полноты |
| На согласовании | формальное решение уполномоченной роли |
| Утверждено | immutable-результат; изменение только новой версией |
| Устарело | входы изменились после формирования результата; не равно ошибке |
| Архив | объект не активен, но доступен истории по правам |
| Качество данных | полнота/валидность/согласованность по правилам |
| Источник | система, файл, пользователь, метод и версия происхождения значения |
| Достоверность/уверенность AI | метрика модели с объяснением; не называть вероятностью без подтверждения методики |
| На дату | исторический временной срез, обычно read-only |
| Период | интервал времени измерений/агрегации |
| Область доступа | организационные объекты и операции, разрешённые пользователю |
| Фоновая задача | импорт, расчёт, отчёт или экспорт, продолжающийся после ухода со страницы |
| Повторить | заново выполнить безопасную операцию; не использовать для создания дубликата |

## 4. Канонические действия

| Смысл | Использовать | Не использовать без причины |
|---|---|---|
| сохранить изменяемую работу | `Сохранить черновик` | `Применить` |
| начать проверку | `Отправить на проверку` | `Готово` |
| вернуть автору | `Вернуть на доработку` | `Отклонить` |
| формально принять | `Утвердить` | `Сохранить` |
| убрать из активного использования | `Архивировать` | `Удалить` |
| прекратить действующую публикацию | `Отозвать публикацию` | `Удалить результат` |
| повторить job | `Повторить запуск` | `Обновить` |
| открыть происхождение | `Показать источник` | `Подробнее` без контекста |
| создать доступ | `Запросить доступ` | `Зарегистрироваться` |
| закрыть overlay без изменения | `Закрыть` | `Отмена`, если нечего отменять |

## 5. Шаблоны сообщений

### Успех

`Черновик скважины WELL-1042 сохранён.`  
`Отчёт поставлен в очередь. Уведомим после завершения.`

### Ошибка поля

`Глубина окончания должна быть больше глубины начала.`  
Не использовать: `Некорректное значение` без правила.

### Предметная блокировка

`Нельзя отправить интерпретацию на проверку: не разрешены 2 расхождения с AI. Перейти к расхождениям.`

### Техническая ошибка

`Не удалось загрузить кривые. Повторите запрос или сообщите поддержке код 7F3A-21.`

### Пустое состояние

`В этом участке пока нет проектов моделирования.` + разрешённое следующее действие.  
Для фильтра: `По выбранным условиям ничего не найдено. Сбросить 3 фильтра.`

### Нет доступа

`У вас нет права просматривать этот объект в участке Северный. Запросить доступ.`  
Не раскрывать дополнительные данные объекта.

## 6. Правила content design

- заголовок страницы отвечает «что и в каком контексте»;
- button начинается с глагола;
- tooltip объясняет термин/иконку, но не скрывает критичное правило;
- одна сущность имеет одно название во всех модулях;
- сокращение раскрывается при первом появлении и в глоссарии;
- число всегда сопровождается единицей и периодом там, где они нужны;
- дата без временной зоны допустима только для календарного бизнес-дня;
- сообщения не обвиняют пользователя;
- AI-формулировка описывает предложение и ограничения;
- demo-расчёт и synthetic data маркируются явно;
- irreversible action называет последствия и объект;
- RU/KZ/EN строки переводятся целиком, не собираются фрагментами.

## 7. Процесс согласования терминов

1. UX writer добавляет термин, определение и контекст.
2. Предметный владелец подтверждает русский вариант.
3. Назначенные редакторы подтверждают казахский и английский.
4. Разработчик использует стабильный translation key, не текст как ключ.
5. Изменение опубликованного термина попадает в журнал решений и проверку всех экранов/отчётов.
