# БГД: реестр и CRUD месторождений

Дата реализации: 25 августа 2026  
Статус: реализовано в кликабельном synthetic-прототипе

## 1. Цель среза

Срез реализует требования пункта 1.4 `GeoBase.pdf`: месторождение является корневым объектом БГД, от которого в дальнейших этапах наследуются участки, залежи, скважины и остальные геологические данные. Пользователь получает отдельный реестр `/geology/bgd` и самостоятельную карточку `/geology/bgd/:depositId`, не переходя к ещё не запрошенным сущностям БГД.

Это демонстрационная реализация: данные детерминированно синтетические, сохраняются в IndexedDB `kapgeo-demo`, переживают перезагрузку браузера и возвращаются к seed через общий reset в профиле. Production API, серверная конкурентность и промышленная модель защиты не входят в этот срез.

## 2. Трассировка пункта 1.4

| Требование источника | Реализация |
|---|---|
| Список месторождений | фильтруемый реестр на `/geology/bgd` |
| Уникальный числовой ID | обязательное уникальное поле `numericId`, неизменяемое после создания |
| Постоянный код объекта | обязательный уникальный `code`, неизменяемый после создания |
| Использовать / скрыть | `isHidden`; скрытые записи не удаляются и доступны через фильтр |
| Тип: месторождение / площадь / иной | `objectType: field / area / custom`; для `custom` обязателен собственный тип |
| Наименование | обязательное редактируемое поле `name` |
| Система координат | краткий код `crs` и необязательное текстовое описание |
| Описание | редактируемое необязательное поле `description` |
| Перечень залежей / участков | вложенные пары `type + name`, добавление и удаление строк |
| Добавление | диалог создания с валидацией обязательных и уникальных полей |
| Просмотр и редактирование | отдельная карточка `/geology/bgd/:depositId` с optimistic version check |
| Удаление | разрешено только при отсутствии зависимых участков, залежей и наборов кондиций |
| Контроль целостности | перед удалением показаны счётчики зависимостей и блокирующее объяснение |
| Одинаковые ID между БГД | неизменяемый уникальный numeric ID явно показан как интеграционный ключ |

## 3. Пользовательский путь

1. Войти под профилем с `geology.view`.
2. Нажать `БГД` в левой навигации или `Открыть БГД` на обзоре геологии.
3. Найти объект по номеру, коду или названию; при необходимости выбрать тип и видимость.
4. Выбрать строку: система открывает самостоятельный URL `/geology/bgd/:depositId`, а фильтры остаются в query-параметрах для возврата.
5. Для создания нажать `Создать месторождение`, заполнить уникальные ID/код, тип, название, CRS, описание и первоначальные участки/залежи; после сохранения откроется новая карточка.
6. На отдельной странице карточки изменить разрешённые атрибуты, добавить или удалить вложенную строку и сохранить новую версию.
7. Переключить `Использовать в рабочих выборках`, чтобы скрыть объект без потери данных.
8. Для физического удаления открыть подтверждение. Независимый объект удаляется; объект с зависимостями остаётся и получает предупреждение целостности.

Редактирование и удаление требуют `geology.well-master.edit`. Пользователь только с `geology.view` видит реестр и карточку в read-only состоянии.

## 4. Доступ к БГД

Реестр и карточки месторождений открываются из основной навигации геологического модуля и используют единый контекст системы.

## 5. Данные и архитектура

- доменная сущность `Deposit` расширена полями пункта 1.4;
- repository принимает внедряемый `DemoDatabase`, нормализует старые IndexedDB-записи и сохраняет совместимость существующего `/geology/master`;
- create/update/delete записывают версии и audit events;
- seed содержит видимые, скрытые и независимые месторождения для демонстрации фильтра и обоих исходов удаления;
- UI использует TanStack Query; объект адресуется path-параметром, а фильтры реестра сохраняются в TanStack Router search params;
- preference `bgdOnlyMode` хранится вместе с platform preferences и получает безопасный default при чтении старого хранилища.

## 6. Состояния и ограничения

Реализованы loading, error, empty-filter-result, read-only, validation error, duplicate, version conflict, dependency warning, success notice и destructive confirmation. Числовой ID и код не редактируются после создания. Архивированный объект остаётся read-only в существующем master workflow.

Не реализованы и не имитируются: серверная синхронизация нескольких пользователей, импорт/слияние разных БГД, специальная процедура изменения ID, промышленная авторизация и каскадное удаление. Эти функции требуют отдельного production-проектирования.

## 7. Обучение и справка

Полная экскурсия содержит шесть шагов БГД: реестр, фильтры и создание показываются на `/geology/bgd`, а редактор и режим фокуса — на отдельной карточке. Добавлен отдельный маршрут `БГД и месторождения`. Справочный центр содержит назначение экрана, роли и основные действия.

## 8. Проверки

Автоматически проверяются:

- нормализация seed и атрибуты пункта 1.4;
- создание, редактирование, скрытие и удаление независимого месторождения;
- уникальность numeric ID и кода;
- запрет удаления при зависимостях;
- persistence и reset `bgdOnlyMode`;
- поведение fixed переключателя;
- валидация URL search;
- наличие `/geology/bgd` и `/geology/bgd/:depositId` в router и каталоге экскурсии.

Финальный milestone закрыт: `typecheck`, 44 test files / 109 tests, `lint` и production `build` проходят; lint содержит только три прежних warnings в несвязанных файлах. Изолированный Chrome QA подтвердил вход под R1, create с custom type и залежью, reload persistence, update/hide, физическое удаление независимого объекта, dependency guard Сарытау, 6/6 target тематической экскурсии и page overflow `0` на desktop 1440 и mobile 390. Дополнительная проверка разделения подтвердила отсутствие редактора в реестре, отдельный detail URL, восстановление поискового фильтра, переход в карточку после create, сохранение detail route, мобильный overflow `0` и возврат в реестр после delete.
