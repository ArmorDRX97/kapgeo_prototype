# БГД: реестр и карточка месторождений

Дата актуализации: 26 августа 2026
Статус: реализованный вертикальный срез кликабельного прототипа

## 1. Назначение

Срез реализует `UC.KAPGEO.BGD.01 Управление списком месторождений`: месторождение является корневым объектом БГД для последующих участков, залежей, скважин и геологических данных.

- реестр: `/geology/bgd`;
- отдельная карточка: `/geology/bgd/:depositId`;
- сохраняемое браузерное хранилище: IndexedDB `kapgeo-demo`;
- общий сброс данных: профиль пользователя;
- production backend, промышленная авторизация и реальная серверная конкурентность не входят в текущий срез.

В самом интерфейсе БГД не показываются служебные слова о постановке, источнике требований или способе хранения.

## 2. Модель данных

### 2.1. Месторождение

| Поле | Правило |
|---|---|
| `id` | технический стабильный ключ маршрута и IndexedDB |
| `code` | единственный пользовательский код; положительное целое число; уникален и неизменяем |
| `nameRu`, `nameKk`, `nameEn` | обязательные названия на трёх языках |
| `descriptionRu`, `descriptionKk`, `descriptionEn` | необязательные описания на трёх языках |
| `objectType` | `field`, `area` или `custom` |
| `customType` | обязателен только для `custom`; позволяет расширять перечень типов без изменения модели |
| `coordinateSystem` | необязательное текстовое поле |
| `isHidden` | исключает объект из обычных выборок без удаления данных |
| `occurrences` | встроенный список залежей |
| `version`, `created*`, `updated*` | версия и сведения аудита изменений |

Отдельных `numericId` и строкового `code` больше нет: это была прежняя ошибочная двойная модель.

### 2.2. Залежь

Каждая строка содержит тип и обязательные `nameRu/nameKk/nameEn`. Тип является текстовым расширяемым значением. Пустые языковые значения и дубликаты типа + русского названия блокируют сохранение.

### 2.3. Совместимая миграция

При первом чтении старой записи repository:

1. использует прежний `numericId` как новый числовой `code`;
2. сохраняет прежний технический `id`, поэтому существующие связи не разрываются;
3. копирует прежнее `name` во все три языковых поля, если локализованные значения отсутствуют;
4. копирует прежнее `description` во все три описания;
5. объединяет прежние `crs`/`coordinateSystemDescription` в `coordinateSystem`;
6. преобразует прежнее `occurrence.name` в три языковых названия;
7. сохраняет нормализованную запись обратно в IndexedDB.

Маркер инициализации отделяет пустой пользовательский реестр от ещё не созданного seed: после удаления всех независимых записей исходные месторождения не появляются самопроизвольно.

## 3. Реестр

Реализовано:

- поиск по числовому коду, RU/KZ/EN-названиям и описаниям, системе координат, пользовательскому типу и названиям залежей;
- фильтр по типу и видимости;
- сортировка по коду, названию, типу, системе координат и состоянию;
- направление `asc/desc`;
- пагинация 5/10/20/50 строк;
- сброс фильтров;
- количество найденных записей;
- отдельные empty state для пустого реестра и отсутствия результатов;
- выбор текущего месторождения;
- сохранение `q/type/visibility/sort/direction/page/pageSize` в URL.

Кнопка `Выбрать` сохраняет `currentDepositId` в platform preferences. Верхний контекст приложения показывает локализованное название выбранного месторождения и первый связанный участок. Если выбранный объект удалён, используется первый доступный видимый объект.

## 4. Создание и редактирование

Форма создания и редактор карточки используют одну модель валидации:

1. код — целое число больше нуля;
2. три названия обязательны;
3. система координат необязательна;
4. пользовательский тип обязателен для `custom`;
5. каждая залежь требует тип и три названия;
6. при создании проверяется уникальность кода;
7. после создания код отключён и отсутствует в update-команде;
8. update использует optimistic version check;
9. конфликт не перезаписывает запись и предлагает загрузить актуальную версию.

В карточке отдельно показаны:

- названия и описания RU/KZ/EN;
- пространственный контекст;
- участки выбранного месторождения;
- встроенные и иерархические залежи;
- версия, автор последнего изменения и видимость;
- dependency summary удаления;
- audit timeline для профиля с `geology.bgd.audit`.

## 5. Права и объектный read-only

Используются отдельные разрешения:

- `geology.bgd.create`;
- `geology.bgd.update`;
- `geology.bgd.delete`;
- `geology.bgd.audit`.

R1 может создавать объекты и изменять назначенное Сарытау либо созданные им записи. R13 управляет всеми записями. R12/R14 видят аудит. Остальные профили с `geology.view` открывают реестр и карточки только для чтения. Проверка выполняется через permission + объект, а не по названию роли внутри компонента.

## 6. Целостность, аудит и состояния

Физическое удаление блокируется при наличии:

- участков;
- иерархических залежей;
- встроенных залежей карточки;
- наборов кондиций.

Create/update/delete/view записываются в audit store. Повторное открытие одной карточки тем же пользователем в течение минуты не создаёт дубликат view-event.

Поддержаны loading, empty, no-results, not-found, repository error, validation error, duplicate code, read-only, archived read-only, version conflict, dependency warning, success notice и destructive confirmation.

## 7. Границы прототипа

Repository boundary имитирует требуемое поведение, но не является production API. Не реализованы:

- серверная синхронизация пользователей;
- настоящий PostgreSQL/Oracle слой;
- промышленная ACL/ЭЦП;
- каскадное удаление;
- процедура администраторской смены кода;
- импорт и слияние сторонних БГД.

## 8. Автоматические проверки

Покрыты:

- seed с одним числовым кодом и RU/KZ/EN;
- create/update/hide/delete независимого объекта;
- запрет повторного кода;
- dependency guard;
- совместимая миграция прежней IndexedDB-записи;
- URL validation для фильтров, сортировки и пагинации;
- маршруты реестра и карточки;
- общая regression suite приложения.

Актуальный результат проверок фиксируется в `docs/implementation-status.md` после финального `typecheck`, `test`, `lint` и `build`.
