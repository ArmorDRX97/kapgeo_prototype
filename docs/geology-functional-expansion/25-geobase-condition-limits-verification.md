# БГД: кондиционные лимиты месторождения

Дата актуализации: 9 октября 2026
Основание: прямой запрос пользователя; заменяет прежнюю привязку к участкам и цикл версий/утверждения.

## Поведение

- На общем экране `/geology/bgd/:depositId` сразу видны все значения единого набора; кнопка «Изменить» с иконкой карандаша открывает форму. Старый `?section=conditions` совместим и показывает общий экран. Участки для работы не нужны.
- Окно «Кондиционные лимиты {название месторождения}» содержит 28 подписанных полей; «Граница вечной мерзлоты» исключена.
- При наличии права изменения и доступа к объекту поля редактируются сразу при каждом открытии. Без прав форма доступна для чтения.
- «Сохранить» обновляет один набор в IndexedDB и закрывает окно. «Отменить», Escape и клик снаружи закрывают без записи. Подтверждений, версий, утверждения, публикации и дат действия нет.
- Ошибка записи отображается в форме, введённые значения сохраняются для повторной попытки. Во время записи повторное сохранение и закрытие недоступны.
- Клавиатурный фокус остаётся в окне и возвращается к кнопке открытия после закрытия.
- Поправки инклинометрии используют набор текущего месторождения без зависимости от участка или статуса публикации.

## Хранение и совместимость

`ConditionSet.depositId` заменяет `siteId`. Детерминированный ключ `CONDITIONS-{depositId}` обеспечивает не более одного сохранённого набора на месторождение. Отдельные записи версий при сохранении больше не создаются.

При чтении старых данных принадлежность определяется через участок. Если наборов несколько, предпочтение отдаётся уже перенесённому набору месторождения, иначе последнему изменённому (`updatedAt`), затем черновику, большей версии и стабильному ID. Используются значения выбранного набора, а не смесь разных участков. Все заменённые исходные записи сохраняются в `meta` под ключами `legacy-condition-set:{recordId}`; прежняя история не удаляется. Недостающие поля добавляются пустыми, сохранённые значения переносятся по ID параметров. Удалённый параметр мерзлоты не попадает в рабочий набор.

## Проверка

Компонентные проверки покрывают единый блок со всеми значениями, редактирование, запись/закрытие/повторное открытие, отмену, Escape, отсутствие мерзлоты и лишних действий, первый набор без участков, ошибку записи и read-only. Repository-проверки покрывают перенос нескольких старых наборов с резервной копией, повторную загрузку, единственность набора, независимость месторождений и отсутствие новых версий.
