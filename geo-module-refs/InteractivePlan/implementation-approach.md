# Предложение следующей реализации

> Историческая постановка исследования. После поручения пользователя выполнен автономный frontend-объём; актуальный статус и отличия — в [отчёте реализации](./implementation-report.md) и [приёмке](./implementation-acceptance.md).

Исследование от 14.10.2026. Все решения ниже имеют статус **предложение**, если не помечены ссылкой на уже принятое решение KAPGEO. Пользователь сейчас поручил исследование; код плана, новые маршруты и хранилище ещё не созданы.

## Проблема и ожидаемый результат

В главном меню уже есть пункт «Интерактивный план месторождения», но он является пустой кнопкой. Существующая карта профиля работает только с документом одного разреза. Она не предоставляет проекты картирования, дерево слоёв, кривые и составные области GeoMap.

Следующая рабочая версия должна позволить геологу подготовить и проверить инженерный план: открыть проект, найти скважины/профили/блоки, включить слои, отредактировать границу и получить чертёж. Просматривающий пользователь должен найти объект и прочитать сведения без изменения плана. Это предлагаемая задача по источникам, а не результат интервью с пользователями.

## UX рабочего места

Сохранить принятые ранее решения о плотной рабочей области и не возвращать громоздкую панель кнопок над рисунком:

- Вход через второй уровень **Геология → Интерактивный план месторождения**. Не добавлять сюда семь методов интерпретации: они остаются третьим уровнем своей рабочей области.
- Слева реестр проектов с поиском и выбором месторождения/залежи. Дерево текущего проекта ниже либо в переключаемом режиме «Проекты / Слои», если одновременно список и дерево отнимают рабочую высоту. Выбор режима сохраняется при возврате.
- Сверху одна компактная строка: название/ID проекта, один статус, справа общие Save/Undo/Redo/экспорт. Развёрнутые реквизиты по кнопке сведений. Общие действия относятся ко всему проекту, Apply/Cancel — к текущей геометрической операции.
- В центре план занимает доступную ширину и высоту. Небольшая группа основных инструментов выбора/рисования и кнопка «Как работать» могут находиться над холстом; полный текст управления — в справке.
- Справа сворачиваемые группы **«Отображение»**, **«Работа с объектами»**, **«Координаты точек»** и сведения выбранного объекта. Ширину подобрать на реальных формах, ориентир существующих рабочих мест — 260 px слева / 340 px справа. Панели независимо сворачиваются, черновик не сбрасывается.
- На узком экране реестр и свойства открываются по кнопкам/в отдельной панели; не зажимать план между двумя постоянными сайдбарами. Клавиатурный доступ и фокус возвращаются к вызвавшей кнопке.

В слое отображения: сетка/оси, подписи, устья/забои, список видимых типов, параметры подложки и легенда. В объектном редакторе: выбранный тип/форма, добавить часть/точку, переместить объект, удалить точку/часть, привязка и стили. Координаты синхронизированы с выбором вершины; части представлены явно, без неочевидных пустых строк как единственного разделителя.

## Данные и состояние

Предлагается независимая модель `MapProject` и namespace хранения. Ни одну скважину не записывать в существующий IndexedDB БГД, `GeologySection` или документ Alpha. Предыдущая автономность разрезов/интерпретации — основание этой рекомендации, но не промышленный контракт источников карты.

| Сущность | Необходимое содержимое |
|---|---|
| MapProject | ID, schemaVersion, название, месторождение/залежь, дата составления, автор, описание, ссылки на слои, печатное оформление |
| CoordinateFrame | Локальная метрическая система, подписи и направления осей, начало/единицы; реальная CRS только после подтверждения |
| Layer | ID, parentId, порядок, имя, видимость, тип/стиль по умолчанию, ссылки на объекты |
| MapWell | Локальный ID/имя/тип, collar(X,Y,Z), bottom(X,Y,Z), атрибуты, положение подписи. Нулевой/неизвестный забой не заменять устьем незаметно |
| MapProfile / MapBlock | Предметные метаданные и направленные сегменты / части контура; отдельно от произвольной декоративной линии |
| ContourObject | ID, слой, имя, open/closed, straight/cardinal/bezier, части, стабильные ID узлов, стиль линии/заливки, атрибуты |
| RasterUnderlay | Локальная ссылка/Blob, привязка и матрица преобразования, прозрачность, видимость; обработка отсутствующего файла |
| ViewState | Камера, выбранный объект/узел, раскрытые группы, отображение подписей. Не геометрия документа |
| EditDraft | Выбранный объект, исходное состояние, временные узлы/табличный ввод, ошибки и preview. Apply создаёт одну команду |

Делить три состояния: незавершённая операция → применённый документ → сохранённый документ. Save не должен незаметно подтверждать неверную точку; уход из проекта предлагает понятный выбор. Undo/Redo предметных команд не отменяет pan камеры. При сбое сохранения правки остаются в памяти и доступны для повторной записи/выгрузки.

Для метаданных/векторов подходит локальный JSON с валидацией Zod, для растров предпочтительнее отдельное локальное Blob-хранилище, чтобы не забивать localStorage base64. Это предложение архитектуры; размер/квота/ошибки записи должны проверяться, а не предполагаться неограниченными.

## Геометрия и взаимодействия

1. Единый обратимый `worldToScreen / screenToWorld`, равный масштаб метров по двум осям. Источники GM25 показывают X вертикально, Y горизонтально; ориентация задаётся адаптером, не переименованием полей. Камера, поиск, импорт, линейка, hit-test и печать используют одну модель.
2. Геометрия преобразуется в экранную систему отдельно от подписей/узлов. Текст, маркеры и экранная толщина не растут при зуме. Печатные стили имеют физические размеры; их нельзя механически приравнивать к экранным px.
3. Приоритет жестов: активная вершина/управляющая точка → активный инструмент рисования/перемещения объекта → выбор объекта → перетаскивание фона. Один pointer не запускает два действия. Default cursor в покое; grabbing только во время pan, согласно прежнему уточнению пользователя.
4. Drag имеет порог, Pointer Capture, отмену Escape/pointercancel/blur; отпускание после drag не создаёт случайный клик/новую точку. При редактировании камеры колесом сохраняется привязка под указателем; незавершённый жест не меняет координатную базу.
5. Привязка задаётся экранным радиусом, переводимым в мировые метры; показываются цель и preview. К забою — точное совпадение. Режим «между забоями» требует двух явных целей; проекция на соединяющий отрезок — предлагаемое правило, а не найденная в руководстве формула.
6. Прямые — ломаные; кардинальные — интерполяционные кривые через узлы; Безье — якоря и пары управляющих точек. Cardinal tension, обработка концов и замыкание описать в расчётном профиле прототипа. Безье из GM25: якоря 1, 4, 7… в последовательности; нельзя считать все точки одинаковыми вершинами.
7. Замкнутые составные области используют even-odd. Внутренние исключения и пересечения допустимы по GM25. Валидаторы разрезного полигона, запрещающие самопересечение, здесь неприменимы без адаптации. Проверять конечные координаты, минимальный состав части и корректность управляющих точек.
8. Выбор по линиям — с постоянной экранной зоной попадания, по областям — по фактической заливке с even-odd. Дерево/инспектор показывают тот же ID; пересекающиеся линии дают список кандидатов. Скрытые/заблокированные слои не редактируются случайным попаданием.
9. Название и атрибуты скважины не обязаны быть постоянно видимы одновременно: переключатели, ручной offset и правила плотности. Число в легенде/инспекторе имеет единицу и источник значения; цвет не является единственным обозначением типа.

## Импорт и вывод

**SVG:** первая реализация — заявленный ограниченный поднабор `path`. Разобрать контуры/части и поддерживаемые команды/transform, показать список неподдержанного. Не вставлять импорт как произвольный HTML/SVG: исключить scripts, события, внешние ссылки и опасные конструкции; проверять объём/числа/число сегментов. Пользователь задаёт единицы, масштаб, ориентацию, поворот и опорные координаты; preview обязателен. GM25 с. 13 показывает эти параметры, но точный порядок вычислений не описан; наш порядок должен быть явным и проверяемым контрольными точками. Исходный файл не уничтожать.

**Растр:** загрузить локальное изображение и привязать известные точки. Для первой версии можно ограничиться масштабом/поворотом/сдвигом по двум опорным точкам; это гипотеза, не геодезическая ректификация. При неизвестных единицах/отсутствии опор показывать ограничение, а не совмещать изображение на глаз как достоверное.

**Вывод:** один построитель печатной сцены для SVG, растрового PNG и браузерной печати. Явные область/масштаб/ориентация/лист/легенда/линейка; камера рабочего окна не меняется. A4–A0 упомянуты в TZ; заявлять только проверенные шаблоны. DXF, EMF/WMF, SHP/DBF — отдельные контракт и проверки, особенно для кривых, отверстий и текстов. «Печать в PDF» не называть отдельным PDF-генератором.

Предлагаемая структура: `pages/geology` — route-композиция; `features/geology-plan` — инструменты/формы/черновики; `entities/geology-map` — типы, геометрия, валидаторы, локальные fixtures; `repository` — независимое хранение; `shared` — действительно общие камера/жесты/инспектор. Обратных импортов между features не вводить.

Начать с SVG: он уже используется, позволяет выбирать и редактировать векторные объекты и выводить чертёж. Отдельно измерить сцену со множеством скважин. Если DOM станет узким местом — статические слои перенести на Canvas, оставив векторный слой выделения/узлов и единое описание сцены. Это возможная оптимизация по замеру, не причина заранее устанавливать Web-GIS-платформу. Внешние тайлы/онлайн-карты для локального инженерного плана не нужны; для реальных CRS и GIS-форматов выбор движка потребуется заново.

## Предлагаемые рабочие этапы

| Этап | Демонстрируемый результат | Проверка выхода |
|---|---|---|
| 1. Просмотр | Рабочий вход, независимый проект, нерегулярная сеть скважин, профили/блоки, сетка, pan/zoom, поиск/сведения | URL/reload/Back, ориентация осей, постоянный размер подписей, совпадение выбора |
| 2. Картографический документ | Реквизиты, дерево/подслои, видимость/порядок, стили, сохранение, dirty guard, история | После reload документ совпадает; чужие хранилища неизменны, Save не дублирует статус |
| 3. Редактор геометрии | Прямые/кривые/составные области, узлы и таблица, move object, even-odd, привязки | Drag не запускает pan; Apply/Cancel/Undo; контрольные примеры отверстий/Безье/сплайна |
| 4. Предметные операции | Локальная скважина/профиль/блок, проверка имени, карточка, линейка, подписи/легенда | Нет записи в БГД; согласованы ID, устье/забой; расстояние 30–40–50 |
| 5. Файлы и чертёж | SVG import preview, подложка, SVG/PNG/печать с масштабом/областью | Контрольные точки преобразования, безопасный импорт, линейка 100 мм при 1:1000 |
| 6. Полная проверка | Права/readonly/empty/error, сохранность черновиков, keyboard/mobile, производительность и документация | typecheck/test/lint/build, браузерные сквозные сценарии, обновлённые каталог/flows/status |

Этапы не являются обещанием сроков и не означают, что нужно останавливаться после каждого. Дальнейшее прямое поручение пользователя определит объём реализации. Межмодульная интеграция, расчётные поля продуктивности/запасов, текущая технологическая телеметрия и промышленная ГИС остаются отдельным расширением.

## Открытые вопросы

- **OQ-MAP-01 — версия и легенда кадра.** GeoMap 2025 наиболее близок, точная сборка и смысл цветных линий неизвестны. До уточнения — собственные явно определённые слои и легенда; не выдавать их за расшифровку исходной базы.
- **OQ-MAP-02 — СК/единицы/ориентация.** Ориентация X/Y подтверждается рисунком, EPSG и трансформация не заданы. До реального импорта — локальные метры, тест обратимости и опорных точек; реальные данные требуют специалиста/паспорта СК.
- **OQ-MAP-03 — общие источники.** TZ требует единого плана и автопередачи во все модули, действующие прототипы автономны. Рекомендация первого среза — автономность; перед интеграцией нужны общие ID, владельцы данных и политика конфликтов, без неё нельзя обещать переход в реальный паспорт.
- **OQ-MAP-04 — расчёт или ручное картирование.** GM25 описывает оформление продуктивности/окисления, но не алгоритм вычисления. Первый редактор — ручная геометрия и готовые синтетические значения. Автоизолинии, интерполяция и запасы потребуют отдельной методики и контрольных примеров.
- **OQ-MAP-05 — сплайн и привязка между забоями.** Нужны параметры cardinal/tension/концов и точное правило snap. Предлагаемые значения/проекция должны фиксироваться как допущения, с воспроизводимыми геометрическими тестами.
- **OQ-MAP-06 — импорт/печать.** Поддерживаемые команды SVG, порядок преобразования, реальная геопривязка растра, форматы/листы и DXF отдельно. Проверять совпадение контрольных координат и физический масштаб; ограничения сообщать до применения.
- **OQ-MAP-07 — доступ/состояния.** Предложение — отдельный permission редактирования, scope проекта и readonly/locked. Не наследовать edit только из geology.view и не вводить промышленное согласование без запроса.
- **OQ-MAP-08 — объём данных.** Нужны целевые плотность скважин/контуров и минимальное устройство. Начать с фиксированного синтетического нагрузочного примера и замера; решение SVG/Canvas принимать по нему.

Вопросы записаны для следующего этапа и сейчас не блокируют исследование. Ни один из них не помечен согласованным только на основании предложения автора этого пакета.
