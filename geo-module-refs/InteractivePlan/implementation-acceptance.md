Дата: 14.10.2026. Относится к автономному frontend-прототипу интерактивного плана. «Реализовано» означает наблюдаемое локальное поведение; ни одна запись не подтверждает промышленную интеграцию или научную методику.

## Автоматические проверки

Проверяются обратимость/ориентация/масштаб координат, zoom anchor, расстояния и snap, even-odd и выбор в отверстии, кривые/разбиение Безье, детерминированность и Zod-модель, дерево и наследование, SVG parsing/rejections, физические листы/масштаб, namespace/права/scope/locked, stale save/delete, corrupt input, квота, точный ввод и Apply без ложного guard, read-only видимость, typed route и возврат через меню.

Финальный прогон: **85 файлов / 380 тестов passed**, 14.10.2026 15:15:10, 22,38 с. `npm run typecheck`, `npm run lint` (0 ошибок/предупреждений), `npm run build` — exit 0. Готовая сборка: JS 1380,42 kB / gzip 393,33 kB, CSS 222,77 kB / gzip 33,92 kB; прежнее предупреждение о размере общего chunk сохраняется. `python scripts/validate_design_skills.py` — 16 навыков validated; `git diff --check` — exit 0. Проверены 37 относительных ссылок исследовательского/реализационного пакета без ошибок.

Первый запуск Vitest в системной временной папке sandbox завершился EPERM до запуска тестов; рабочий обход — TEMP/TMP внутри `.tmp/map-vitest` только для процесса проверки. Конфигурация приложения и пользовательские HOME/CODEX_HOME не менялись.

## Браузерная проверка

Официальный Playwright CLI, изолированная headless Chrome-сессия `map-qa`. Chrome crashpad внутри sandbox не запускался; для QA использован разрешённый запуск вне sandbox и собственные локальные Vite/preview на 4175/4176. Существующий сервер на 4173 не изменялся.

Успешно пройдены:

- Поиск/выбор/центрирование, таблица → Apply → Save → reload, Undo после Save → повторный Save → Redo.
- Фон pan, grabbing только во время жеста, wheel zoom и неизменный размер текста, drag узла без pan, Cancel геометрии.
- Guard незавершённой операции, Stay, смена проекта, locked read-only.
- Создание кардинальной области и второй части/отверстия, сохранение составной геометрии.
- SVG с двумя path, реальный геометрический preview, применение и отдельные объекты; реальные скачивания SVG и PNG, визуальный просмотр результата.
- Слой/подслой → сохранение → reload; рабочая ссылка меню и возврат к проекту.
- Локальная скважина (устье/забой), Безье с добавлением якоря 4 → 7 точек, реальная линейка относительно масштаба камеры.
- Локальная растровая подложка → Save → reload; SVG содержит встроенный `data:image/png`; печатный iframe содержит финальную SVG-сцену.
- Создание/удаление временного проекта без ложного dirty guard. Нативное подтверждение удаления наблюдалось; для повторного автоматического прогона confirm принимался stub только в QA-контексте.
- R3 просматривает, R7 не имеет доступа по прямому URL, неизвестный проект получает fallback. R1/R13/scope/locked дополнительно покрыты repository-тестами.
- 1440×900 и 390×844: нет горизонтального overflow страницы, карта имеет рабочую ширину; кнопка инструментов на mobile доводит до панели. Выполнен визуальный просмотр скриншотов.

Артефакты: `.tmp/design-qa/map-flow.js`, `map-create-files.js`, `map-files-rest.js`, `map-advanced-final.js`, `map-release.js`; снимки `map-initial.png`, `map-locked.png`, `map-mobile.png`, `map-mobile-tools.png`, файлы `map-output.svg/png`, `map-raster-output.svg`. Ошибок `pageerror` в завершённых сценариях не было. Первоначальные favicon 404 — существующее сообщение; это не ошибка редактора.

Готовая production-сборка дополнительно прошла обычный вход → hash-маршрут проекта → поиск → таблица → Apply/Save/reload → SVG download. В изолированном QA-origin намеренно повреждённый JSON дал error-state, скачивание исходного текста сохранило `{broken`, восстановление исходного JSON + Retry вернуло сохранённый план. Page errors — 0. Артефакты: `map-release-desktop.png`, `map-release.svg`, `map-corrupt-backup.txt`.

Небольшой замер pan готовой сцены в headless Chrome: 41 интервал requestAnimationFrame, p95 17,1 мс, максимум 17,2 мс. Это наблюдение одного локального прогона при 180 скважинах/24 построениях; оно не устанавливает промышленный SLA и не проверяет 5000 объектов. Для текущей сцены переход на Canvas не потребовался.

Не проверялись физическая печать, реальный PDF-файл из системного диалога, сенсорный pinch, промышленные объёмы/браузеры, реальная СК и внешние данные. Проверка ограниченного набора не является SLA производительности.
