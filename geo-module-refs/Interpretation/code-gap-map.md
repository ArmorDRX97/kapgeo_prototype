## Технические ограничения, заметные по коду

1. `InterpretationMode` сейчас только `lithology | technology | core`. Расширение методов требует маршрутизации и модели, а не переименования вкладок.
2. `InterpretationDocument` не содержит ГК/Кф/ЛФТ/фильтра/ЗПО/цемента/металла/контролей/РМ. Добавлять по предметным структурам с миграцией Zod, а не один универсальный список интервалов со скрытыми полями.
3. `CurveSpec` не хранит дату/прибор/роль записи/происхождение. Тип кривой не различает КМ от КМр и первичный ТК от ТК перед РМ. Это потребность отдельной записи измерения, а не нового цвета.
4. `search.ts` ограничивает окно 160 м; стартовые параметры Workbench 112–136 м; `CurveEditor` подписывает шаг 0,1 м. Перед новыми скважинами/нерегулярными точками убрать эти fixture-зависимости соразмерно реализации.
5. `calculateTechnology` допускает только положительный RS и использует упрощённые пороги/экстремумы. Не переиспользовать его как общий движок ГК/ПС/ТМ/РМ: единицы, отрицательные значения, пропуски и методики различаются.
6. `TrackSpec/IntervalSpec` позволяют кривые и прямоугольные интервалы. Произвольные линии фона, редактируемые уровни, конструкции, точечные метки и гистограмма потребуют новых контролируемых overlay-примитивов. Не переводить всё на SVG только потому, что он есть в разрезах.
7. Устаревание сейчас проверяется для кернового `sourceRevision` и параметров preview КС. Для комплекса нужны зависимости результата от конкретных версий записей, поправок и других методов; сохранённый результат не должен молча считаться актуальным.
8. ACL интерпретации сейчас даёт edit **R1/R2/R13** при `scope=interpretation-demo` и `status=draft`; у разрезов edit только R1/R13. Не переносить ограничения разрезов на интерпретацию без нового решения. Источник: [permissions](../../src/shared/auth/permissions.ts) и `canEdit` Workbench.
9. В [domain-tokens](../../packages/geo-viz/src/domain-tokens.ts) прямо отмечена условность геологической палитры. Визуальное сходство с Альфой и соответствие СТ НАК — разные степени подтверждения.
10. Старые документы второго среза называют наборы DEMO-101…104; фактические ID — `int-demo-01…04`, коды в текущем UI — WELL-101…104. При ссылках/миграциях использовать актуальные ID.
