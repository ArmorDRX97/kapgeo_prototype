# Backlog по новой записи: 18 задач

Текущий статус: **все 18 пунктов реализованы в автономном прототипе**, см. [матрицу приёмки](./implementation-acceptance.md) и [отчёт](./implementation-report.md). Ниже сохранён исходный backlog аудита, где «Сейчас» описывает состояние `5f45bf7`. P0 — исправить предметный смысл демонстрации; P1 — завершить связный рабочий сценарий; P2 — уточнение/дополнение по руководству. Порядок и технические решения предложены по результатам аудита, не являются дословным планом участников. Источники времени — [транскрипция](./audit/transcript-medium.txt), кадры — [индекс](./evidence-index.md). Вопросы Q-VA-* раскрыты [здесь](./decisions-and-questions.md).

## Карта

### VA-01 · P0 · Убрать цветные демонстрационные области из основной сцены

**Основание:** прямые повторные просьбы 05:18–05:31, 08:00–09:27; [пример до правки, 09:15](./audit/keyframes/t-0555.jpg).

**Сейчас:** четыре вложенных области, отдельная область с исключением, несколько декоративных границ доминируют над скважинами/блоками (`fixtures.ts`, слои `geo/zones/boundary`).

**Сделать:** основной пример — чистый инженерный план скважин, геоблоков и профилей. Удалить из него эти декоративные заливки/«кольцо». Возможности произвольных областей, even-odd и кривых можно сохранить в редакторе; демонстрационный пример этих возможностей не должен выдавать их за обязательную геологическую карту. Не добавлять отдельный демонстрационный проект без необходимости.

**Приёмка:** при открытии свежего примера и после миграции старого локального примера цветные пятна не появляются; предметные блоки/скважины читаются сразу. Пользовательские сохранённые построения не стираются молча. Координатная сетка остаётся доступной. Зависимости: VA-03, VA-09.

### VA-02 · P0 · Убрать неподтверждённые линии и ложные предметные названия

**Основание:** 11:15–15:05 — красные линии обсуждают без окончательного определения, предлагают пока не показывать.

**Сделать:** убрать из начального геологического примера декоративные линии, смысл которых не задан; не называть их окислением только по цвету. Не запрещать красный цвет всем объектам: выделение, текущий профиль и пользовательский стиль — другие сценарии. Не удалять все линии профилей вместе с лишним контентом.

**Приёмка:** у каждого видимого типа есть понятное назначение и запись в легенде/инспекторе. Начальная сцена не содержит «границ окисления», основанных только на предположении о legacy-красных линиях. Q-VA-01 остаётся открытым.

### VA-03 · P0 · Перестроить синтетические блоки по скважинам

**Основание:** 08:20–08:58, 10:18–11:14, 18:04–18:21; [legacy, 10:05](./audit/keyframes/t-0605.jpg), [наш произвольный блок, 09:15](./audit/keyframes/t-0555.jpg).

**Сделать:** небольшой согласованный пример (предложение: 3–5 блоков с десятками характерных скважин, а не обязательный новый лимит объектов). Прямые замкнутые контуры соединяют выбранные скважины; формы и ориентация различаются, возможны соседство и наложение. Реальные координаты/названия месторождения не копировать.

**Приёмка:** вершины, заявленные как скважинные, совпадают с соответствующими точками скважин численно и на экране; произвольных четырёхугольников между ними нет. Блок не становится автоматически выпуклой оболочкой всех скважин. Наложение двух блоков не вызывает ошибку само по себе. Для устья/забоя зафиксировать выбранное прототипное правило, Q-VA-03. Зависимости: VA-04, VA-08.

### VA-04 · P0 · Сделать связь «контур блока ↔ скважина» устойчивой и видимой

**Основание:** 18:34–19:08 — добавляется точка контура, которую подводят к существующей скважине. Хранение ссылок — предлагаемое решение.

**Сейчас:** snap возвращает координату ближайшего забоя/проекции между забоями; `parts.nodes` хранит только X/Y, ссылка на скважину и состав блока отсутствуют.

**Сделать:** выбирать скважину при создании/добавлении вершины, подсвечивать цель привязки, показывать связанную скважину в координатах. Хранить стабильную ссылку (`wellId` и явная цель устье/забой — предложенная форма) либо эквивалентный локальный контракт. Отдельно обозначать свободную вспомогательную вершину; разрыв связи — явная команда. Список скважин блока не выводить из совпадения имён.

**Приёмка:** добавить точку → привязать → Apply → Save → reload; ссылка, контур и состав блока согласованы. Undo/Redo восстанавливает связь. Drag узла не двигает камеру/скважину. Скрытая или недоступная цель не выбирается случайно. Предусмотреть чтение существующих документов без ссылок. Q-VA-03.

### VA-05 · P0 · Защитить координаты скважин в сценарии карты

**Основание:** 02:41–02:59 и 18:34–19:08 — скважины не меняют, корректируют блок. Это уточняет более широкий старый РП, допускающий редактирование скважин.

**Сделать:** обычный просмотр/редактор блока не предлагает drag устья/забоя, перемещение всей скважины и изменение её X/Y в общей таблице точек. Инспекция, выбор как опоры и чтение координат остаются. Предлагаемый первый вариант — геометрия исходных скважин карты read-only; отдельный режим создания/изменения исходной скважины отложить, если он не нужен для следующей демонстрации. Не расширять права БГД.

**Приёмка:** при выборе скважины и попытке drag/numeric edit её координаты не меняются; фон по-прежнему перемещает вид, контур — собственные вершины. Сообщение объясняет ограничение. Переиспользованные тесты на свободное перемещение скважины пересмотрены под новое правило. Q-VA-06.

### VA-06 · P0 · Исправить знак скважины и линию направления

**Основание:** 15:20–18:04; повторный ASR подтверждает явную критику «палочка и крестик в конце».

**Сейчас:** все устья — пустые круги; крест рисуется в конце сегмента до забоя, независимо от типа. Отдельная реализация есть в интерактивном Canvas/SVG, экспорте и карте профиля разреза.

**Сделать:** основной знак — читаемый круг с внутренним крестом/плюсом и цветом типа; линия направления заканчивается без декоративного креста. Вариант пустого круга вводить только с явной семантикой/легендой, не угадывать. Знак имеет постоянный экранный размер при zoom. Общий визуальный контракт переиспользовать в SVG/PNG/печати и согласовать с картой профиля; не менять знаки всех прочих модулей автоматически.

**Приёмка:** одинаковый смысл знака на экране и выводе; линия не дублирует крест на конце; размер/подписи читаемы на разных масштабах. Q-VA-02 и Q-VA-07. Зависимость: VA-07.

### VA-07 · P1 · Типы скважин и предметная цветовая легенда

**Основание:** 15:53–16:36, 17:05–18:04; [вырезка легенды](./audit/details/well-legend.png).

**Сделать:** тип — явное поле/локальный классификатор; символ и цвет выбираются согласованно, легенда объясняет оба. В основной сцене показать хотя бы обсуждаемые откачные, закачные, наблюдательные, разведочные. Остальные видимые legacy-категории зафиксированы в аудите; не объявлять их все обязательными бизнес-типами. Пока нет обещанной таблицы, цветовую схему обозначить как предварительную. Не определять тип по чётности/суффиксу номера.

**Приёмка:** изменить тип → согласованно обновились знак, цвет, подпись инспектора, легенда и экспорт. Неизвестный тип имеет явное нейтральное отображение. Q-VA-02.

### VA-08 · P1 · Правдоподобная нумерация и читаемые подписи

**Основание:** 09:37–10:30, 11:04–11:14; пример 110 / 110.1 / 110.2 дан участниками.

**Сделать:** придумать синтетические номера блоков и скважин с понятными сериями, согласовать их состав. ID отделить от отображаемого номера. На обзорном масштабе приоритизировать имена блоков/профилей, вторичные числа выводить по настройке или наведению; на увеличении раскрывать детали. Это предложение по читаемости, а не отдельная устная просьба о новом алгоритме declutter.

**Приёмка:** номер находится поиском и в дереве/инспекторе; нельзя перепутать подпись блока с номером скважины; одинаковые координаты не закрывают сведения без выбора кандидата. Тип не вычисляется из номера. VA-03.

### VA-09 · P1 · Привести слои к предметным группам

**Основание:** 05:18–05:31, 08:00–09:27; РП с. 112 разрешает раздельное отображение скважин, разрезов, блоков.

**Приёмка:** включение/выключение каждой группы влияет только на неё; скрытые объекты не ловят клики; тип/цвет предметного объекта не определяется положением в случайном слое. Сохранённые пользовательские слои доступны после обновления. VA-01/02.

## Разрезы

### VA-13 · P0 · Проверить и исправить расположение исходных контактов

**Основание:** 20:48–21:15, 21:28–21:38; [технология](./audit/keyframes/t-1245.jpg), [литология как образец](./audit/keyframes/t-1290.jpg), [руда](./audit/keyframes/t-1295.jpg); РП с. 154–155.

**Сейчас:** `layerAnchors()` уже строит top/bottom от from/to; визуальный дефект нельзя автоматически объяснить отсутствием расчёта. Есть отдельные дорожки, экранные offsets, исходные и дополнительные интервалы, коррекции/продления.

**Сделать:** для каждого режима сопоставить источник MD → траекторию → X/Z → колонку → вершину контура → маркер. Исправить расхождения/смещения, если подтверждены. Литология остаётся эталоном поведения; руда и забаланс используют собственные интервалы, не границы любой породы. Развести координату ствола и экранное смещение дорожки.

**Приёмка:** таблица контрольных from/to, X/Z и координат маркеров минимум для двух наклонных скважин; точки совпадают с началами/концами соответствующих интервалов при zoom/pan, вертикальном увеличении и изменении колонок. Проверены «Технологический горизонт», оба режима руды и «Технологический забаланс». Фиксированные контакты не перемещаются произвольно. Не маскировать проблему простым скрытием точек. Q-VA-05.

### VA-14 · P1 · Различить исходные, вспомогательные и выклинивающиеся вершины

**Основание:** 20:48–21:38 и уточняющий РП с. 154–155.

**Сделать:** показать тип/источник и доступное действие для каждой точки, чтобы допустимые межскважинные вершины не выглядели случайными контактами. Переиспользовать существующие ограничения опор, дуг и выклинивания; добавить недостающую визуальную/инспекторную ясность. Не объявлять все зелёные точки свободными.

**Приёмка:** фиксированный контакт, вспомогательная точка, выклинивание, граница разреза и продолжение к забою различимы по информации и доступным действиям. Для ограничения «только Z» невозможно изменить X через drag или таблицу; Undo/Cancel не меняет источник. VA-13.

### VA-15 · P1 · Уточнить и расширить стадии/классификацию разрезов

**Основание:** 20:18–20:30; РП с. 136.

**Сейчас:** только `stage: exploration | operation`; `kind: main | auxiliary` существует отдельно.

**Сделать:** отделить стадию изучения от основного/вспомогательного типа и предполагаемого технологического назначения. Руководство перечисляет поисковые, поисково-оценочные, разведочные работы, детальную разведку, эксплуатационную разведку и эксплуатацию. Предлагается расширить стадии по РП и группировку/фильтры реестра; финальное соответствие слову «технологию» требует Q-VA-04.

**Приёмка:** тип и стадия не смешаны; старые записи читаются с явно описанным fallback, фильтры/подписи/сохранение согласованы. Не создавать новый модуль «детальные разрезы» по одной неясной реплике.

### VA-16 · P1 · Сделать сценарий «разрез → сегмент → скважины» явным

**Основание:** 20:30–20:38; РП с. 137–145.

**Сейчас:** профиль — массив XY-вершин; состав скважин общий `wellIds`, группы скважин для расчёта сегментов временные в `ProfileEditor`.

**Сделать:** пользователь видит выбранный разрез, направление и номер сегмента, его начало/конец и связанные скважины. Переиспользовать профиль, состав и расчёт, не дублировать три редактора. Если вводится сохраняемое распределение скважин по сегментам, определить устойчивые segment ID, правила общей вершины/неоднозначной проекции и последствия удаления/разворота. Это предложенная детализация короткой реплики.

**Приёмка:** выбрать/создать разрез → добавить/выбрать сегмент → добавить существующие скважины → увидеть их проекцию → Apply/Save/reload. Изменение порядка/удаление сегмента явно показывает судьбу связей; не исчезают ручные области. Q-VA-04/05.

### VA-17 · P1 · Закрыть дельту инструментов карты профиля по РП

**Основание:** 19:34–20:42; РП с. 142–145.

**Уже есть:** новый профиль, независимый сегмент с присоединением, продолжение, drag вершины, snap, добавление скважины, табличное удаление вершин/состава, расчёт и подбор по коридору.

**Проверить/доработать:** явное удаление выбранного сегмента на карте, осмысленное переключение включить/исключить скважину (сейчас карта только добавляет), выравнивание выбранного конца по забою, понятность независимого/сопряжённого сегмента. Сохранить валидаторы зависимостей и предпросмотр. Не считать отсутствие кнопки идентичной desktop-иконке отсутствием возможности вообще.

**Приёмка:** команды выполняются и с клавиатуры/точными координатами; удаление сегмента и исключение скважины предупреждают о затронутых связях; добавление узла/сегмента не создаёт новую исходную скважину. VA-16.
